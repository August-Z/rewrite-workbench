## RWB-001 · 初始化最小 workspace、依赖与合成 fixtures

目的：建立可以实际编译和测试的最小 Rust 核心，不提前搭建整个产品。

交付：选择并锁定 Rust 工具链、Oxc 同一版本系列和 Cargo.lock；创建 core/CLI 最小模块边界；合成 TSX fixtures 与 expected 分类；文档中加入真正执行过的 setup/test 命令。只有 UI 开始时再锁定前端依赖，或在此任务中以明确子项完成，不能安装后不记录。

验收：至少一个 TSX 输入解析成功；一个 parse error 被报告；alias 与 shadowing 的可行性 spike 有真实测试；README 能准确指导下一位开发者重复运行。此任务不需要完整 UI、不需要修改用户项目、不发布包。

## RWB-002 · TSX 直接导入与绑定分类

交付：从 JSX 使用追到同文件命名 import 的 binding；区分其他模块同名、局部参数/变量遮蔽、DOM 标签、type-only 导入、未解析来源；输出稳定原因码与用户可读说明。

验收：正反例覆盖直接导入、as 别名、参数与块级遮蔽；default/namespace/re-export/wrapper 等不支持形式不得误判为已确认来源。匹配 moduleSpecifier 的语义与 [architecture](architecture.md) 一致。

## RWB-003 · 不可变修改计划与 patch 输出

交付：文件 hash、输入快照、版本化 EditPlan；UTF-8 半开范围；expectedText；重叠/同位置插入处理；内存应用与 unified patch。

验收：中文/emoji/CRLF/BOM 与 EOF 边界测试通过；无关字节保持；重叠或原文不匹配拒绝生成结果；同输入与配置得到确定性输出。core 不直接写入目标文件。

## RWB-004 · 两种 JSX 改写操作

交付：`jsx_attribute_rename`、`jsx_string_value_map`；拟定 recipe schema 的解析与版本检查；与 binding、EditPlan 组合形成 CLI 垂直路径。

验收：目标属性已存在、重复属性、spread、动态值、来源未知均按契约分类；改后重新解析；有效迁移重复执行不产生新增改动；每种操作有真实端到端 fixture。不得把任意 before/after 自动转换列为已经实现。

## RWB-005 · 本地项目服务与请求协议

交付：只绑定 loopback 的本地入口、项目根与文件范围、静态 UI 资源、查询/取消/导出接口；generation/snapshot 贯穿协议；本地会话与 Origin 约束；路径规范化与符号链接边界。

验收：不允许客户端任意指定外部文件读取；旧请求结果失效；取消后资源收敛；不执行被扫描项目的 package scripts；错误和空结果状态明确。该服务在 alpha 不提供目标源码写入接口。

## RWB-006 · 工作台的完整可视化流程

交付：React/TypeScript/Monaco 界面；打开文件、选择操作、预填与确认条件、候选分类、解释、diff、勾选、patch 导出、recipe 保存。

验收：与 CLI 相同快照/条件生成一致计划；用户改变条件不会继续显示旧结果为当前；empty/loading/error/cancelled/stale/unsupported 均有处理；键盘、浅深色与窄屏可用。固定 fixture 只能标为演示，不得冒充真实解析。

## RWB-007 · 竞品与用户任务对照

交付：按 [competitive baseline](research/competitive-baseline.md) 记录同任务最佳竞品方案；按 [launch validation](research/launch-validation.md) 记录目标用户独立试用。

验收：区分冷启动与熟练后任务、正确率与速度、工具版本与人工指导；无测量数据时明确写未开展。用户招募等待不阻止 M1/M2 开发；没有操作优势时产生一个可执行的调整决定，不能伪造通过或无限阻塞。

## RWB-008 · 受保护的直接应用

交付：显式应用入口、文件内容与 expectedText 检查、冲突结果、部分失败报告与可恢复的输出记录；与纯分析核心隔离。

验收：预览后文件变更不能覆盖；一次写入失败有准确报告；不以旧备份覆盖外部后续修改；不宣称跨文件事务或任意编辑器并发安全。所有已展示补丁与实际写入一致。

## RWB-009 · 安装分发与版本验证

交付：先验证 macOS arm64、Linux x64；版本标识、校验和、许可证/notice、安装与卸载说明、最小 smoke fixture；锁定实际 release 工具流程。

验收：在干净或明确记录的环境运行安装命令和基本操作；未验证的平台不得列为支持；无假包名或未来命令。包发布为独立明确授权动作，先准备可审阅的产物。

## RWB-010 · 使用真实核心的公开样例体验

交付：公开合成样例、可修改条件、真实匹配与 diff；优先相同 Rust core 的 WASM 构建；若采取其他路径，记录语义一致性与额外维护成本。

验收：浏览器样例与 native core 同 fixture 结果一致；不上传用户源码；分享内容只包含用户明确选择的公开内容；不依赖私有路径、API key 或人工固定返回值。

## RWB-011 · v0.1 发布与传播实验

交付：准确 README、短演示、支持/不支持矩阵、变更记录、真实安装步骤、已知问题与按来源记录的分发计划。

验收：发布资料与 release 产物一致；得到发布动作所需授权；不自动联系他人或刷 Star；记录曝光、GitHub 点击、同期 Star 与自发分享的不同证据，不把时间相关当作逐人归因。评测样本不足需在决策中明示。

## RWB-012 · 根据实际案例决定扩展范围

交付：对收集到的第二类任务做频率、可表达性、竞品与维护成本判断；只选择一个下一版重点，形成决策记录与可验收任务。

验收：扩展有具体可复现案例；说明为何现有操作或工具不足；新增语义边界与回归成本明确。无充分证据时可以改善现有体验或暂停扩张，不能为了 roadmap 看起来丰富而承诺多语言平台。
