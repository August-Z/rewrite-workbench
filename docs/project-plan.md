# Rewrite Workbench 项目计划

版本：1.0（项目启动计划） · 日期：2026-09-09 · 状态：已选定方向，等待实现与实证验证。

本文件是产品范围和交付意图的依据；工程细节见 [architecture](architecture.md)，进度见 [status](status.md)，时间与任务见 [roadmap](../ROADMAP.md) 和 [backlog](backlog.md)。

## 1. 产品定义

把一次手工代码修改，变成看得懂、可验证、能重复执行的项目级改写。

目标用户已知道想怎么改业务代码，但不愿为一次任务学习 AST、规则 DSL 或编写转换脚本。产品从实际代码出发，帮助用户明确条件、检查真实候选、生成最小补丁，并把条件与正反例保存为可复用 recipe。

首个场景是 React/TypeScript 组件 API 调整。架构使用 Rust，但用户获得的直接收益应是更低的操作成本和可检查的正确结果。

## 2. 目标与成功标准

项目的首要外部目标是开源传播与真实 GitHub Star 积累；不将收入、企业采购或服务端用户量替换为首要目标。

产品目标：普通前端开发者可独立完成一次支持范围内的修改，理解哪些位置被改、哪些被排除、哪些无法判断。

工程目标：变换行为可复现；修改计划与固定快照绑定；未知或冲突不静默改写；无关源码尽量保持原字节。

这些目标相互关联但证据不同。fixture 正确、任务完成更快不自动证明会获得 Star。已有竞品的高 Star 也不是本项目的增长预测。

验证分三条记录：

- 正确性：标注 fixture、真实仓库样例、端到端输出。
- 体验：安装/启动时间、正确任务完成时间、所需指导、规则迭代次数。
- 传播：有记录的目标曝光、GitHub 点击、同期净增 Star、自发引用和第二个真实场景。

## 3. 用户与使用场景

| 用户 | 任务 | 希望避免的成本 |
| --- | --- | --- |
| 业务前端开发者 | 把旧组件属性/固定值迁移到新约定 | 手动逐处确认、同名误替换、反复审阅无关 diff |
| 组件库维护者 | 提供一项可重复执行的升级规则 | 每次重新讲解迁移、维护复杂脚本入口 |
| 代码维护者 | 把一次确定的修复推广到多处 | 依靠文本模式误伤相似代码 |

第一批使用场景应能通过两个受限操作表达。复杂跨组件逻辑重构、性能修复、自动类型迁移不作为第一版演示。

## 4. 用户流程

1. 在本地项目启动工具；工具只分析用户明确指定的目录。
2. 打开 TSX 文件并选择目标属性或组件，或从操作模板进入。
3. 选择“属性改名”或“字符串值映射”；由选中代码预填参数。
4. 确认 import 来源字面量、导入名称、属性、旧值/新值和文件范围。
5. 查看候选分类与原因；逐处检查差异，排除不需要的匹配。
6. alpha 导出 patch；后续版本通过独立受保护写入路径直接应用。
7. 保存 recipe 和最小正反例；再次运行时重新分析当前源码。

自由编辑 before/after 是后续产品假设。首版由用户选择两种预设操作，根据当前节点预填字段，再由用户确认条件；不自动识别 before/after 差异，也不从正反例自动归纳条件。保存正反例用于验证与复现，并不意味着已实现规则推导。

## 5. MVP 范围

| 能力 | alpha 约定 |
| --- | --- |
| 输入语言 | TSX；共享解析基础可支持 JS/TS，但第一条用户流程与验收聚焦 TSX |
| 组件归属 | 直接命名 import 的声明来源、导入名称、同文件 alias 与 shadowing |
| 操作一 | 显式 JSX 属性改名，已有目标属性/重复/spread 等按明确条件拒绝或待处理 |
| 操作二 | 某属性的明确字符串值映射；动态表达式不猜测 |
| 输出 | 候选、原因、快照绑定的 EditPlan、diff、patch、recipe |
| 执行 | 本地 Rust core 与 CLI；alpha GUI 调用相同核心 |
| 配置 | 用户可见业务条件；版本化 JSON recipe 在文件中保存 |
| 未知情况 | 原文保留、给出原因；不隐藏 parse error 或扫描缺口 |

暂缓：完整 TS 类型推断、最终物理包身份、barrel/re-export 链、namespace/member 导入、包装组件追踪、任意 AST DSL、JSX spread 自动迁移、Vue/Svelte、云端私库处理、多用户系统。

## 6. 交互设计原则

- 一屏包含操作条件、候选位置、差异与理由，尽量避免让用户先进入 AST 树。
- 普通术语优先：组件来源、属性名、旧值、新值、文件范围；语法节点只在深入调试中出现。
- 机器状态统一使用 ready、not_matched、skipped、conflicted、invalid；界面分别展示“可改写、未匹配、跳过、冲突、无效”。“未修改”也要能解释，文件错误不能伪装成零命中。
- 候选总数标明扫描范围；不将局部扫描结果显示为全仓覆盖。
- 选择变化立即使旧结果失效；耗时任务可取消，进度不伪造百分比。
- 本地代码默认不上传；公开样例体验明确与本地目录操作区分。
- 支持键盘操作、可读浅色/深色主题、宽度变化、长路径、中文和 emoji。

固定样例交互稿只能用于讨论设计；正式演示不得用固定输出冒充分析引擎。

## 7. 技术决策与实施边界

初始核心采用 Oxc parser + semantic。它提供文件内符号与作用域能力，不等于完整 TS 类型系统或跨文件最终来源追踪。

先实现两种受限 recipe，不自造通用模式匹配语言。只有任意模式需求经验证后，才评估 ast-grep 与 Oxc 的组合，记录双 AST 对应及位置编码复杂度。

本地 CLI 负责项目发现、显式范围、文件快照与输出；浏览器界面使用 React/TypeScript/Monaco。本地 HTTP 技术、Rust/Node 工具链、Oxc crate 版本在首次可编译 spike 时统一选定并锁定，不凭设计文档声称兼容性已验证。

核心分析与文件系统/HTTP/UI 解耦，为后续 WASM 样例体验保留边界。首版无需数据库、云账号、桌面壳、规则市场或大模型 API。

## 8. 质量与风险

| 风险 | 应对 | 需要的证据 |
| --- | --- | --- |
| 错改同名符号 | 根据绑定确认直接导入；未知跳过 | alias、参数/块级遮蔽、其他模块同名 fixture |
| 修改后行为不符合意图 | 用户明确定义迁移规则与前置条件 | 正反例、项目现有检查；不宣称语义等价 |
| 字符位置错误 | Rust 保持 UTF-8 byte edit；UI 边界转换 | 中文、emoji、CRLF、BOM fixture |
| 预览后文件变更 | 不可变快照、内容 hash、请求 generation | stale preview 与并发写入端到端测试 |
| 变成已有工具的薄包装 | 同任务公平对照，关注所需知识和时间 | 实际竞品计时、目标用户独立试用 |
| 演示好看但 Star 很少 | 记录目标曝光及后续行为 | 有分发记录的公开实验；不购买或交换 Star |
| 范围膨胀 | 两操作优先，新增能力需对应真实任务 | 每次扩展的 issue、验收与成本说明 |

## 9. 交付与资源安排

参考节奏：两周完成正确性底座与垂直实验，四周左右完成本地 alpha，第五至第六周起准备公开 v0.1。该时间依赖实际投入、兼容性发现和评测结果，不是固定上线承诺。

主要负责人负责范围、依赖、合并、GitHub 发布和最终验收。Agent 可承担限定模块实现、fixtures、UI 或独立审查；并发写入要划定文件边界，外部发布和主线 Git 操作由一人串行完成。

竞品研究与用户接触不阻止基础开发。未完成的外部评测作为明确缺口进入发布/扩张判断，不能被虚构为通过，也不能把整个项目无限挂起。

## 10. 开源与传播

README 使用英文入口，中文计划辅助本地开发和中文贡献者。首个公开演示展示一个实际完成的代码任务、误匹配排除与可复用规则；安装步骤必须对应真实发布物。

早期分发优先公开样例、技术文章、短演示和有上下文的社区反馈。每个渠道记录日期与目标受众，避免只有总 Star 数却不知道是否触达。

许可证为 MIT；保留上游依赖声明。公开素材只使用自建或许可适当的代码，不上传个人业务仓库或会话内容。

## 11. 项目管理与 agent 连续性

- `AGENTS.md`：短入口与稳定工程规则。
- `docs/status.md`：事实性进度、证据和下一项任务。
- `ROADMAP.md`：阶段结果与门槛。
- `docs/backlog.md`：有依赖与验收的任务。
- `docs/architecture.md`：有效技术契约。
- `docs/decisions/`：已做决定与变更原因。
- GitHub issues/milestones：当前执行状态与协作讨论，链接到上述文件。

新对话先从仓库读取这些文件。日常进展只更新相关状态，避免把全部聊天和日志复制进长期指令。仓库文档能被 Codex 和其他 coding agent 使用，无需私人全局配置才能理解。

## 12. 下一步

从 RWB-001 开始：建立最小 Rust workspace 与合成 fixture 项目，选择并锁定依赖，验证 TSX 解析与文件内绑定路径。不要第一步就创建完整 UI、迁移市场或多语言通用框架。
