## 验收与错误符号风险

| 要求 | 实际覆盖 |
| --- | --- |
| 直接命名 import 与本地别名 | 原名、as、quoted export name、escaped module literal；按导出名选择，不能用本地别名冒充导出名。 |
| 参数及块级遮蔽 | 解构参数、声明前引用、嵌套 closure、var hoisting、catch、循环变量、具名函数表达式、局部类；离开作用域恢复 import。断言各引用对应的独立声明 spans。 |
| 其他模块同名与 barrel | 其他包、相似 subpath、`./barrel` 都不冒充选定包；显式选择 `./barrel` 仅确认该 import 声明。路径大小写和 `..` 不归一化。 |
| DOM 与未解析来源 | 小写同名 import 不改变 intrinsic JSX；custom-element、未声明标识符、只有 named/star/namespace re-export 的引用不确认来源。 |
| type-only | 声明级、specifier 级、default、namespace type-only 均跳过；同名局部值参数/变量按实际局部声明判断。 |
| 不支持形式 | default 含 `{ default as B }`，namespace、TS import-equals、source/defer phases、member/namespaced/this JSX；wrapper、变量赋值、解构、require、稍后赋值不追踪来源。 |
| 不误报 ready | 全部 golden entries 断言状态、原因与 bindingConfirmed；只有选定直接命名值绑定确认，但仍未评估操作。 |
| 错误文件 | 在已有匹配 JSX 后追加 malformed/recoverable JSX、无效正则或重复 lexical 声明，整份报告 invalid 且 bindings 为空。 |
| 字节与 CLI | 中文、emoji、组合字符、BOM、CRLF、无末尾换行精确位置；CLI 前后输入字节相同，selector 变化影响结果；错误输入退出 1，参数/编码错误退出 2。 |

## 提交前复核与修正

逐项复核 source、fixtures 和 CLI 后，发现 Oxc 0.149.0 会将某些 import 与同名局部/类型声明合并到同一 SymbolId，且不报 Semantic syntax error。原先仅以 SymbolId 在 import 索引中存在就确认来源，会错误确认 `const Button = Local; import { Button } from "@example/ui"; <Button />`，反向声明顺序也可复现。

已新增 `merged-bindings` golden fixture，先运行见到失败，再修复为 `skipped / unsupported_merged_binding`。分类器检查 Oxc 的全部 redeclarations，按输入顺序保留每个声明 span，不选择某一个 import 作为唯一来源。回归覆盖变量先/后声明、namespace、函数签名、interface、enum、class、type-only import 与局部值合并；同文件独立的普通命名 import 仍可确认。即使某些 TypeScript 合并形式合法，也保守跳过，未实现完整类型和值合并推理。

修正后新增单项回归通过，并对最终运行时代码完成 workspace 29 个测试、fmt 和 Clippy。最初的 28 测试结果不替代这次修正后的验证。后续只补充交付链接和状态，按文档变更检查。
