## 实测 API 结论与限制

Oxc 0.149.0 的 `SemanticBuilder::new()` 默认不构建节点存储。首轮测试发现编译成功但所有 binding observations 为空；读取固定版本源码后增加 `with_build_nodes(true)`，绑定用例全部通过。此配置不能因“只需要 Semantic”而移除。解析同时显式开启 `parse_regular_expression: true` 和 `with_check_syntax_error(true)`，错误输入不使用恢复树产生绑定证据。

首次工具链安装在已完成组件安装后触发 rustup 自更新错误；使用上表的 `--no-self-update` 命令再次确认成功。Clippy 检出的两个多余 `u32` 转换已移除；它们没有改变诊断坐标语义。

正常输入的 `skipped / binding_spike_only` 只说明本次只读检查结束，任何观察都不是 `ready` 候选。`other_binding` 尚未细分局部声明、default/namespace import 等情况；`typeOnly` 为 AST 观察字段，完整 type-only 候选行为留给 RWB-002。没有 recipe、EditPlan、内容 hash、版本化请求、修改操作或 patch。

本次未验证真实 TSX 工程迁移、完整 TypeScript 类型检查、改写幂等/字节保持、UI、WASM、安装包、CI、用户体验或增长指标。Unicode fixture 证明本次 binding span 定位，不代替未来 edit 与 UI 坐标转换验收。

下一任务为 **RWB-002 / Issue #2**：以此 spike 为基础实现直接导入选择与完整候选/原因分类；其 RWB-001 依赖已满足。
