# rewrite-workbench 验证计划

本文是计划中的验证与阶段验收要求，不是已通过的测试报告。项目当前的实现、安装和性能状态必须以实际执行记录为准。核心范围与拟定 JSON recipe 协议见 [architecture.md](./architecture.md)。

首版计划只验证两种操作：指定直接导入组件的 JSX 属性改名，以及指定属性的固定字符串值映射。Alpha 仅导出 patch；v0.1 才加入带内容 hash 检查的直接应用。后续 WASM 公开样例复用同一核心和 fixture。

## 1. 证据层次与记录方式

| 证据 | 能支持的结论 | 不能替代的验证 |
| --- | --- | --- |
| Recipe schema 校验 | 配置版本、字段和操作参数符合协议 | 是否命中正确节点 |
| Golden fixture | 给定输入与规则得到预期修改和跳过原因 | 对任意工程都正确 |
| Parser + Semantic 检查 | 结果能按选定语法模式解析，所需绑定与语法条件成立 | 完整 TS 类型检查和业务等价 |
| Patch 检查与实际应用 | 导出的 patch 能产生预览中的字节结果 | 页面行为和类型兼容 |
| 项目原有 typecheck/test | 在记录的项目环境中通过对应检查 | 覆盖所有运行时行为 |
| 安装与平台验证 | 指定平台上能启动和完成目标流程 | 全平台兼容 |
| 基准测量 | 指定机器、语料、版本与测量方法下的性能 | 未测项目的速度倍数 |

每次正式验收计划记录：提交/构建标识、依赖与工具链版本、recipe 内容或 hash、语料来源、操作系统与机器、执行的检查、结果、未覆盖范围。引用源码文档只能支持设计可行性，不能写成已经运行通过。

## 2. Fixture 结构

每个 fixture 计划包含最小输入文件、recipe、期望输出文件、期望候选/原因摘要及简短说明。支持只读的多文件 fixture，但首版仍按文件内语义判断。特殊字节用例需要保留原始文件，不能经测试加载器统一换行或移除 BOM。

正例验证预期修改；反例验证没有修改以及跳过/排除原因。不得只断言“有输出”或照抄实现分支。每个 fixture 要说明它防止哪类实际误改。

### 2.1 来源和作用域

| 场景 | 计划期望 | 主要风险 |
| --- | --- | --- |
| 直接命名导入组件 | 命中指定组件 | 基础功能缺失 |
| import as 别名 | 命中本地别名的引用 | 只比较标签字符串 |
| 不同模块导入同名组件 | 排除 | 来源误判 |
| 函数参数遮蔽组件别名 | 排除该作用域中的 JSX | 改到局部组件 |
| 块级声明、嵌套函数遮蔽 | 仅处理仍绑定到 import 的引用 | 作用域遍历错误 |
| 同文件同时存在命中与遮蔽引用 | 只改正确子集 | 把局部结论扩展到全文件 |
| type-only import | 不作为运行时组件来源 | 混淆类型与值 |
| 小写 DOM 标签 | 不作为导入组件命中 | 仅靠名称匹配 |
| namespace/default import | Alpha 跳过并报告能力范围 | 首版未定义来源语义 |
| 从本地 barrel 导入同名导出 | 不推断为目标包；按声明字面来源处理 | 跨文件来源假设 |
| 包别名或 tsconfig paths 指向 shim | 不宣称验证物理包身份 | 把字面来源当成解析后来源 |
| 包装、赋值、解构后的组件 | 跳过 | 缺少数据流却推断来源 |

Oxc 的 BindingIdentifier 在 Semantic 阶段取得 SymbolId，Scoping 提供已解析引用和作用域查找；fixture 将独立验证选定版本对上述语法的实际行为。[BindingIdentifier](https://docs.rs/oxc_ast/latest/oxc_ast/ast/struct.BindingIdentifier.html)、[Scoping](https://docs.rs/oxc_semantic/latest/oxc_semantic/struct.Scoping.html)

### 2.2 JSX 属性改名

| 场景 | 计划期望 |
| --- | --- |
| 唯一显式旧属性，目标属性不存在 | 只替换旧属性名 |
| boolean 简写属性、表达式值、字符串值 | 属性名改写保留完整值和书写形式 |
| 多行属性和属性间注释 | 不改变无关字节 |
| 旧属性不存在 | 不命中 |
| 已存在目标属性 | conflicted，不自动覆盖或合并 |
| 旧属性重复出现 | conflicted |
| 任意位置存在 JSX spread | Alpha 整个目标元素 skipped |
| 自闭合与成对元素 | 结果一致；不改无关 closing element |
| 规则新旧属性名相同或目标名无效 | 配置校验拒绝 |

### 2.3 固定字符串值映射

| 场景 | 计划期望 |
| --- | --- |
| 指定属性的值与 change.from 相同 | 只替换字符串内容 |
| 单引号与双引号 | 各自保留原引号风格 |
| 空字符串 | 按明确字符串比较，不与缺失值混淆 |
| 相似前缀、大小写不同、其他属性相同值 | 不误命中 |
| size={"small"}、size={variable} | skipped，不求值 |
| 模板字符串、调用结果、条件表达式 | skipped |
| JSX spread 或重复目标属性 | 分别 skipped/conflicted |
| 实体、引号、反斜线、换行等特殊值 | Alpha 未支持时明确 skipped；扩展支持前验证 JSX 解码和编码语义 |
| 新旧值相同 | 配置校验拒绝 |

## 3. 编辑和协议不变量

下列检查计划直接验证编辑系统，而不是为每个 UI 控件重复测试：

| 不变量 | 覆盖输入 | 期望 |
| --- | --- | --- |
| UTF-8 范围合法 | 中文、emoji、组合字符、Unicode 标识符 | edit 始终位于合法字节边界 |
| UI 定位一致 | 相同文本的 UTF-8/UTF-16 来回映射 | 高亮、diff 和导出指向同一段源代码 |
| 原始字节保留 | LF、CRLF、BOM、无末尾换行、缩进 | 未被 edit 覆盖的字节完全一致 |
| 原文前置条件 | expectedText 被改变 | 拒绝使用旧 edit |
| 区间不重叠 | 嵌套命中、重复命中、相同位置插入 | 明确去重或报告冲突，不静默覆盖 |
| 顺序确定 | 不同任务完成顺序、不同扫描顺序 | 候选排序、edit 与 patch 可重复 |
| 幂等 | 对迁移后的文本再运行同一规则 | 不再产生改动 |
| 配置严格 | 未知 schemaVersion、未知字段、拼写错误 | 清楚报错，不静默降级 |
| 计划绑定快照 | 相同路径、不同内容 hash | 旧计划失效 |
| 请求 generation | 较慢旧请求晚于新请求返回 | UI 不显示旧结果为当前结果 |
| 取消与关闭 | 扫描中取消、关闭会话 | 停止可取消工作，不发生导出/写入副作用 |

Oxc 提供 UTF-8/UTF-16 转换代码；采用现有转换工具仍需要覆盖本项目的 BOM、换行及 Monaco 映射，不能只测试 ASCII。[Oxc 坐标转换](https://github.com/oxc-project/oxc/blob/main/crates/oxc_ast_visit/src/utf8_to_utf16/mod.rs)

结果检查计划重新运行所选版本的 Parser 和必要 Semantic 语法检查。解析错误输入不得生成可应用 edit；生成结果若新增语法错误，应把对应修改标为 invalid。对需要正则表达式完整解析的验证配置，原型需确认相关 feature 与 ParseOptions，不能把默认 Parser 成功直接称为完整语法验证。[Oxc Parser](https://docs.rs/oxc_parser/latest/oxc_parser/)、[Semantic builder 源码](https://github.com/oxc-project/oxc/blob/main/crates/oxc_semantic/src/builder.rs)

## 4. Alpha patch 与 v0.1 写入验证

### Alpha

计划在临时测试工作区中验证：

1. 导出的 patch 只包含选中的 ready 候选，应用后与预览结果逐字节相等。
2. 工作区已有其他未提交修改时，patch 不带入它们。
3. 零命中、全部跳过、部分冲突分别给出准确摘要，不把未修改误报为成功迁移。
4. 扫描、预览和导出全过程不写入源文件，不暂存、不提交、不清理 Git 状态。
5. patch 文件名、编码与换行能被所支持的平台处理；不使用基于 HTML 的转义文本替代真实补丁。

### v0.1

直接应用涉及覆盖风险，计划补充以下必要检查：

| 场景 | 计划期望 |
| --- | --- |
| 预览后文件内容改变 | hash 不匹配，拒绝旧计划 |
| 文件内容变但 mtime/大小相同 | 仍能检测冲突 |
| 文件删除、替换、变成符号链接 | 拒绝或报告清楚，不越界写入 |
| 部分文件无权限或写入失败 | 报告实际已写/未写集合，不声称整体成功 |
| 写入后恢复请求遇到外部新修改 | 不使用旧备份覆盖新内容 |
| 进程中断或单文件替换失败 | 不遗留被截断的源文件；报告可恢复信息 |
| 用户选择部分候选 | 只应用同一快照下经过验证的选中子集 |

hash 检查只构成乐观并发保护；原子替换也不能提供跨文件事务。验收记录必须保留这个边界，不以测试中未出现竞态来宣称任意外部写入均被阻止。

## 5. 本地 HTTP 与工作区边界

计划保留少量集成用例覆盖有实际影响的服务边界：

- 无会话凭据、错误 Origin/Host 的请求被拒绝；服务默认只能从本机回环地址访问。
- 绝对路径、父目录穿越、越界符号链接不能读取或写入选定工作区外的文件。
- recipe 中不能执行脚本；打开 UI、扫描目录和导出 patch 不会隐式启动工程命令。
- 超限请求、超大文件和失效会话有明确结果，避免无限加载或资源耗尽。
- API 错误与日志不泄漏无关源文件内容；源代码不产生未声明的网络上传。

这些检查在 transport 或文件读写边界变化后运行；纯文案修改不重复执行完整服务测试。

## 6. 真实仓库与语料来源规范

计划选用可以公开引用且许可证允许的仓库或人工整理 fixture。公开验收材料不得包含私人仓库源码、私有依赖名称、个人路径、访问凭据或未经许可的第三方数据。

每份真实语料计划记录：

- 仓库 URL、许可证、固定 commit SHA、使用的相对目录及获取日期。
- 是否保留完整源码、仅保留最小复现，或使用下载脚本获取；附带所需归属说明。
- 原始安装/检查方式、锁定依赖及运行环境；若不能重现则明确标注，不能算作通过。
- 规则为何适用于该仓库、哪些位置被人工确认、为何跳过其他位置。
- 如为测量而人为植入待迁移属性，显式标为合成改写语料，不能宣称真实项目需要这项迁移。

首批验收计划覆盖不同规模和不同格式习惯的公开 React/TSX 工程；工程数量不替代案例质量。必须包含一个混有别名、局部遮蔽和不同组件来源的语料。尚未选定的仓库不写成已验证对象。

## 7. 基线、项目检查与性能

### 正确性基线

对真实工程先记录原有 typecheck/test 结果，再检查候选结果。原有失败要单独记录；不能把旧错误归因于改写，也不能因为改写没有增加错误就称工程全部通过。验证应在独立测试副本中进行，保留实际被改动文件列表与完整 patch。

项目原有检查通过，只支持该检查覆盖的结论。Oxc Semantic 不是完整 TypeScript typechecker，不能在 UI 中用“类型安全”概括词法绑定确认。[Oxc TypeScript 边界](https://oxc.rs/docs/guide/usage/transformer/typescript.html)

### 性能测量

正确性 fixture 通过后，才计划对固定语料测量枚举、读取、解析、Semantic、匹配、计划生成、diff 和总耗时。记录峰值内存、文件数、总字节、候选数、机器及冷/热缓存；大目录未必代表大解析输入，不仅按文件个数宣传。

竞品比较计划使用相同源文件、相同功能范围、相同计时边界，并保存命令、配置和版本。如果一个工具只做结构匹配，另一个额外做绑定分析，需要分别展示匹配阶段和完整工作流，不用不等价总耗时制造速度倍数。工具若不支持同一任务，应报告能力差异而不是人为补齐后称原生支持。

速度目标与安装包大小预算将在原型基线后确定。未测量前不发布“快若干倍”或“支持任意规模工程”等承诺。

## 8. 阶段验收

| 阶段 | 计划交付 | 必须通过的最小门槛 | 不要求作为前置条件 |
| --- | --- | --- | --- |
| 技术原型 | 固定依赖版本；两种操作的最小核心与位置转换 | 直接导入、alias、shadowing、冲突跳过、Unicode 定位和最小 edit fixture | 完整 UI、用户访谈、竞品完整计时 |
| Alpha | 本地 UI、候选原因、diff、JSON recipe、patch 导出 | 两操作 fixture 表覆盖；一次完整导出流程；不写源文件；基本 HTTP/路径边界 | 直接应用、多平台全覆盖、跨文件语义 |
| v0.1 | 支持平台的分发、hash 检查应用、清楚的失败报告 | 对应安装检查；并发冲突与部分失败用例；真实工程固定版本验收 | 完整 TS 类型系统、任意模式语言 |
| WASM 公开样例 | Web Worker 中运行共享核心 | 与原生版同 recipe/fixture 的结果一致；过期请求与编码验证；浏览器体验检查 | 浏览器任意文件系统访问、大仓库多线程能力 |

开发主线不以外部访谈、竞品长时间测量或所有真实仓库全部可安装为统一前置条件。等待外部反馈或计时任务时，可以继续推进与其无依赖的 fixture、协议、UI 和文档工作。未完成的对照只限制相关宣传结论，不自动阻断其他已经有验收依据的开发。

## 9. 变更对应的最小检查

| 变更 | 计划执行 |
| --- | --- |
| 纯文案、规则说明、路线图 | diff、相对链接、协议和阶段一致性；不运行项目构建 |
| recipe schema 或参数语义 | schema 正反例、对应操作 fixture、示例 JSON 一致性 |
| 匹配、import 索引、作用域判断 | 来源/遮蔽 fixture、受影响操作 fixture及相应真实语料 |
| edit 或坐标转换 | Unicode/BOM/CRLF、重叠 edit、字节保持、预览与 patch 一致性 |
| 任务调度或缓存 | generation、取消、缓存键与确定性检查 |
| HTTP 或路径处理 | 对应边界集成用例和一个正常完整流程 |
| 直接应用逻辑 | hash 冲突、权限/删除/替换、部分失败及恢复检查 |
| 依赖升级 | 按变更影响重跑解析/绑定/坐标或打包检查；保留仍有效的其他结果 |
| UI 布局 | 对应界面视觉检查和关键交互；无底层变化时不重复大型性能测量 |

所需检查通过后即结束本次验证。只有相关变更、新失败或具体未覆盖风险出现，才扩展或重复检查。验收报告计划同时列出已确认结果和仍未验证的边界，不用漫长检查清单代替判断。
